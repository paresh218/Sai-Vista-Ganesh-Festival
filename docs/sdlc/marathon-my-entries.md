# Private marathon entries — 11 November 2026

The signed-in email, verified server-to-server by the existing resident authentication service, owns entries. Flat number, request reference, browser email, resident flags and display names never authorize access. Family entries using the same verified email appear together. Unknown, expired, revoked and mismatched sessions fail closed. No private entries are returned through GET/public counters.

The grid shows one row per matching entry. An expandable read-only details section returns that entry’s submitted email, DOB, phones, flat, gender, blood group, emergency and guardian details, medical response/note, fee and historical payment reference. It shows whether a screenshot was received, without exposing the committee’s private Drive URL or raw image. Internal payload digests and authentication tokens are not returned. Rows exist only in page memory; sign-out and new sign-in clear the grid and invalidate late responses.

Editing accepts only BIB print name (1–30 characters) and existing allowed T-shirt sizes. An explicit field allowlist rejects attempts to alter identity, distance, payment or BIB number. Ownership is checked again under the existing script lock. A revision rejects stale edits; only columns K (shirt) and AA (print name) are written. Existing confirmation emails are not resent. The original submission digest remains for safe retry acknowledgment and is never used to authorize edits.

The service needs Apps Script’s external-request permission to verify the current session with the existing committee authentication service. No Clerk secret is copied into the marathon service and no new external service is added. Tests cover cross-account references, field allowlist, untouched columns, expired/revoked sessions, minimal response shape, concurrent edits, client sign-out and late responses. Production verification must not alter a real participant just to test the edit flow.

Inline-grid update: rows start read-only, Edit enables only print name and T-shirt size, and Cancel restores saved values. Only one row can be edited at a time. A modal blocks interaction while saving and prevents Escape/duplicate saves; success or error requires acknowledgment. Success uses the server’s returned row. Failure reloads authoritative rows (including an ambiguous response) or clears unavailable data rather than showing an unsaved draft as stored. Multiple-family-entry and blocker regressions run without altering production entries.
