## Security / privacy / activation boundary
ASVS 5.0.0 applicable areas: validation, file handling, access control, resource limits, private data minimisation, dependency provenance and logging. WCAG 2.2 AA is the design target, not a conformance claim. No new paid services/runtime dependency for payments. Sensitive fields are stored privately only after deliberate submission, not in site analytics or application browser storage. Screenshots do not authenticate payments; committee must check actual bank/UPI credit. Signature checking is not fraud detection or malware scanning. The public group invite is a convenience shown after submission, not a security boundary.

Backend deployed as version 2 under saivistaculturalcommittee@gmail.com in a separate marathon project. Private workbook, receipt folder, Yes/No validation, edit trigger and five-minute sweep were created. Drive metadata confirms only committee ownership on workbook, folder and checked proof. Frontend configuration points to the verified service; readiness returns acceptingEntries=true. Old event/gallery services remain unchanged.

Google documents per-account MailApp daily quotas (free consumer accounts generally 100 recipients/day) and installed triggers run with their creator's authority: https://developers.google.com/apps-script/guides/services/quotas and https://developers.google.com/apps-script/guides/triggers/installable. The queue respects remaining quota rather than circumventing it with additional scripts/accounts.
