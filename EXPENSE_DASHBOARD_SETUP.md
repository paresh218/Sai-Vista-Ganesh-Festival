# Live expense dashboard setup

Version 2 endpoint is connected in expense-dashboard.js. Live JSON verification on 6 September 2026 found 17 recorded expenses totalling ₹1,01,295, 14 planned items without amounts, and a remaining balance of ₹4,95,893 from ₹5,97,188. The sheet summary excludes ₹4,040 of Janmashtami expenses; the dashboard deliberately calculates from individual records. Website publication is a separate step.

1. Open the accounts spreadsheet, then Extensions → Apps Script. Add the code in `expense-source.gs` to that project. If a doGet already exists, integrate the expense route into it rather than creating two doGet functions.
2. Set EXPENSE_YEAR to the year used for text dates without a year (currently 2026). Prefer real spreadsheet dates or dates with four-digit years.
3. Recommended: name the actual Total Collection amount cell `DashboardTotalCollection` using Sheets named ranges. That reference follows moved cells. Otherwise the reader requires exactly one `Total Collection` label with its collection amount immediately to its right. It never uses the Amount Left column or wing/surplus subtotals. If that summary's columns are rearranged, use the named range.
4. Keep one expense table with unique headers Festival, Expense, Item, Amount, Paid On. These headers may be reordered or moved to another row/column/sheet. Spelling must stay the same (case and whitespace are ignored). Records end at a row whose Item is Total Expenses or Total Collection and whose Festival and Expense fields are blank. Summary rows beneath that boundary are ignored. Keep unrelated tables below this explicit boundary. Invalid populated records cause totals to be withheld instead of silently omitted.
5. Blank Festival/Expense cells inherit the preceding value within an uninterrupted group. A new festival resets the category; blank rows reset both. Missing categories show Uncategorised. Set category cells explicitly if blank cells should not inherit. Rows with an item but no amount or date are listed separately as planned and excluded from totals. Festival/category-only placeholder rows are ignored. An amount missing beside a paid date is an error. Missing dates remain visible as Not recorded and are excluded from date-filtered results.
6. Deploy → Manage deployments → Edit the supplied deployment → New version → Deploy. Use the existing deployment to retain the configured URL. The website needs a JSON endpoint accessible to its visitors. This makes the five expense fields and collection amount available to that audience; the endpoint does not return unrelated sheet columns. Keep private notes out of the Item field.
7. Visit the /exec URL and verify it returns JSON with ok:true. Reload the website and compare its full totals against the sheet before publishing. Browser fetch must succeed from the website origin.

The live dashboard refreshes every 60 seconds while visible, on returning to the tab, and manually. It recalculates each full snapshot, including changed/deleted rows and negative adjustments, in integer paise. The overall balance always includes all records; filters affect only the breakdown. Failed refreshes visibly mark retained results as outdated. No sample totals are embedded in production.

Sample-only verification: the 15 supplied records total ₹31,295 (Janmashtami ₹4,040; Ganpati ₹27,255), leaving ₹5,65,893 from ₹5,97,188. The live sheet additionally contains Mandap and Mahaprasad advances of ₹50,000 and ₹20,000.

Run `node expense-model.test.cjs` for calculation and parsing checks. Deploy the updated website files together, including the two new JavaScript files and service-worker.js.
